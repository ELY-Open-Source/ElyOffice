# Ely Office 0.1.10 update film: production contract

A 90-second release film, 1920×1080 at 60 fps. Light, funny and gorgeous: a motion and UI/UX designer's showreel. The visual language:

- **Liquid Motion.** Glossy candy-glass liquid that sticks, strings out, merges, splits, bounces, squashes and stretches. It is rendered by our own WebGL engine (`lib/liquid.js`), so you "can pinch it".
- **Aurora + glassmorphism.** A deep indigo aurora field moves behind everything (owned globally; scenes do not touch it). The UI is frosted glass (`lib/ui.css`).
- **Every transition passes through liquid.** UI melts into drops, and drops grow into UI.

The music is 120 BPM: 1 beat = 0.5 s and 1 bar = 2 s. Land key hits on beats (multiples of 0.5 s), and land section changes on bar lines (even seconds).

## The liquid engine (LQ)

Your `scenes/sN.liquid.js`:

```js
LQ.add({ id: "s3", start: 18, end: 26, build: function (lt, P, t) {
  // lt = local seconds (0 at the scene start), t = global seconds. Pure function of time:
  // NO state between calls, NO Math.random (use LQ.M.rng(seed) re-created per call), NO Date.
  var M = LQ.M, C = LQ.C;
  P.ball(960, 500, 120, C.mail);
}});
```

Coordinates are CSS pixels, with (0,0) at the top left and y pointing down. That matches the HTML, so liquid and DOM line up 1:1.

Primitives (each call adds one; at most 40 per layer per frame; they all melt together with smooth-min "goo"):

| Call | Shape |
| --- | --- |
| `P.ball(x, y, r, color, {sx, sy, rot, k, clear})` | ellipse (sx/sy scale the radius: squash and stretch; rot in radians) |
| `P.cap(ax, ay, bx, by, ra, rb, color, {k, clear})` | tapered capsule from A (radius ra) to B (radius rb): strings, necks, drips, tails |
| `P.box(cx, cy, w, h, radius, color, {rot, k, clear})` | rounded rectangle (full width/height) |
| `P.ring(cx, cy, radius, halfWidth, color, {k})` | ring (shockwaves, O shapes) |
| `P.tri(x0,y0, x1,y1, x2,y2, round, color, {k})` | rounded triangle (flaps, arrows, paper planes) |
| `P.text(slot, spec, x, y, {scale, color, amount})` | liquid typography from a blurred text field. slot 0 or 1. spec = `{text, font: '900 220px "Inter"', w, h, blur: 12, align: "center"/"left"/"right", pad, lh}` (w×h is the field box in px, centred at x,y). `amount` 0..1 thins and grows the letters |
| `P.morph(specA, specB, x, y, f, {scale, colorA, colorB})` | ONE liquid field blended from text A (f = 0) to text B (f = 1): melting one word into another. Uses both slots. Give both specs the same w/h/blur; `align: "left"` keeps a shared prefix still |
| `P.layer(1)` | the following calls go to the FRONT canvas (above the UI). `P.layer(0)` goes back |
| `P.material({bevel: 34, refr: 22, gloss: 1, body: .42, frontBody: .82, shadow: [10, 26], shadowA: .45})` | per-frame material (rarely needed) |
| `P.textK = 26` | goo radius between text and other liquid |
| `P.fade = 0..1` | multiplies the whole back canvas (fade to black) |

- `k` is the merge radius in px. Small (10–20) = crisp contact. Large (50–90) = very sticky, with fat necks. Two blobs closer than ~k fuse.
- `color` is a hex string or [r, g, b] (0..1). Neighbouring colours blend through the neck.
- `clear: 1` makes a nearly colourless water or glass drop that refracts the aurora.
- Text fields are cached by spec, so changing `text` every frame (a counter) is fine. Use at most about 60 distinct strings.
- The front layer has no aurora behind it, so use it for liquid that must sit ON the glass UI (drops landing on a panel, a blob over a button).

`LQ.M` motion helpers (all pure functions of time):

`clamp, lerp, prog(t, a, b) → 0..1, smooth, outCubic, inOutCubic, outBack(x, s), inCubic, spring(t, t0, freq, damp) → 0..1 with overshoot, wobble(t, t0, freq, decay, amp) → decaying sine, bounce(t, t0, h0, g, restitution) → height above floor, rng(seed), hex, mix3`.

`LQ.C` colours: `doc #3D7FE5, table #2E9E5B, show #F07B2A, pdf #E0344F, mail #1E8FE0, tree #7E57C2, mark #F2A900, white #F4F6FF, violet #7B5CFF, pink #FF5FA8, cyan #2FD8E8, peach #FFB46B, lime #B8F35A`.

### Liquid craft (what makes it feel real)

- **Volume is conserved.** When something stretches, it gets thinner; when it squashes, it gets wider (sx × sy ≈ 1).
- **Stretch along velocity.** A falling drop is a tall teardrop (a ball with sy > 1 plus a thin cap tail above). On impact it squashes (sx 1.5, sy 0.65) and then wobbles back (`M.wobble`).
- **Splitting means a neck.** Two balls move apart joined by a `cap` whose radius shrinks with distance. When the neck gets thin (< 4 px), drop it, and let both halves recoil (a wobble). A tiny satellite droplet left in the middle is delicious.
- **Merging means a neck forms before contact.** The goo k does this automatically; then the merged blob overshoots and settles.
- **Anticipation:** squash slightly before a jump. **Follow-through:** jiggle after landing. **Overshoot:** springs, not linear tweens. Secondary drops trail main drops.
- Nothing sits perfectly still for long: let resting blobs breathe (a ±1.5 % scale sine) and drift a few px.
- Keep it legible: few, purposeful blobs beat noisy fields of them.

## The HTML layer (sub-composition)

`scenes/sN.html` is a HyperFrames sub-composition. Keep exactly this skeleton: put everything inside `<template>`, style the root by `#sN-root`, and give every id an `sN-` prefix.

```html
<template>
<style> #s3-root { position: absolute; inset: 0; } /* ... */ </style>
<div id="s3-root" data-composition-id="s3" data-width="1920" data-height="1080" data-duration="8"> ... </div>
<script>
(function () {
  var root = document.getElementById("s3-root");
  var w = ElyKit.mailWindow(root, { id: "s3", select: 0 });   // canonical window + refs
  var tl = gsap.timeline({ paused: true });
  // ... tl.fromTo(...) at LOCAL seconds (0 = scene start)
  window.__timelines["s3"] = tl;
})();
</script>
</template>
```

- GSAP 3 is global. Use `fromTo` (seek-safe), never `from` or `.play()`, and no `Date` or `Math.random`.
- The local time of the HTML timeline equals the `lt` of your liquid build, so they line up.
- Global classes come from `lib/ui.css`: `.glass` (frosted panel, absolute), `.glass.soft`, `.glass.solid`, `.pill`, `.pill.blue`, `.candy` (glossy chip, set `--c`), `.ico`, `.kicker`, `.title-zh`, `.title-en`, `.grad-text`, and every `.mw-*` class of the mail window. The CSS vars are `--mail --doc --table --show --pdf --tree --mark --violet --pink --cyan --peach --lime --ink --ink-2 --ink-3 --line --sans --zh --mono`.
- Fonts: Inter (Latin), Noto Sans SC (Chinese), JetBrains Mono (code). Use `font-family: var(--sans)` / `var(--zh)` / `var(--mono)`. If lint reports `font_family_without_font_face`, add the matching `@font-face` rules (copy them from `lib/ui.css`, but use urls `assets/fonts/...`) inside your template `<style>`.
- `ElyKit.icon(name)` returns an inline SVG string. The names are inbox send draft outbox archive trash star clip search pen sync contacts reply replyAll forward flag folder shield image bell filter check cloudOff wifi mail lock download upload file sparkle undo redo chevron tray plus x eye eyeOff terminal chip snow. Size it with CSS width/height; the colour is `currentColor`.
- `ElyKit.mailWindow(el, {id, select, box, outbox})` builds the canonical window. It returns `{win, side, list, rows (NodeList), read, search, query, placeholder, compose, sync}`. `ElyKit.MAIL` holds the 8 sample mails, `ElyKit.ACCTS` the 3 accounts; `ElyKit.row(m, i, sel)`, `ElyKit.avatar(m)` and `ElyKit.reader(m)` return HTML strings for more rows and readers.
- The UI language is Simplified Chinese (the app's zh-CN interface). English appears where real content is English (sender names, subjects).
- **Do not invent features.** Show only what this brief says ships. Use no third-party logos: provider names are text chips.
- **Do not animate `.clip` elements or set visibility on them.** Wrap things and animate the wrappers.
- Animate transforms, opacity and filter. A "camera move" = transform a wrapper div around the window (scale + translate), eased `power3.inOut` over 0.8–1.2 s.
- Typing effects: reveal characters with a deterministic per-character schedule (a fixed cps with slight seeded jitter), plus a blinking caret.
- Design quality bar: crisp alignment to an 8 px grid, consistent radii (12 / 16 / 20 / 28), generous spacing, real-looking content, nothing clipped by accident, nothing overlapping the caption zone. Every element enters with motion (stagger 0.04–0.08 s, spring or `back.out` eases) and exits gracefully (or melts into liquid).

## Sound-effect cues

`scenes/sN.cues.json` is a JSON array of `{ "t": <global seconds>, "sfx": "<name>", "gain": 0..1 }`, one cue per audible event that is visible on screen. The names you can use:

`bloop` (a drop lands or pops into being) · `drip` (small droplet) · `splash` (big impact, splits) · `stretch` (a rubbery pull, a neck forming) · `snap` (a neck breaks) · `pop` (a bubble or chip appears) · `merge` (a gloopy merge) · `whoosh` (a fast move) · `swoosh-up` (rising) · `click` (a button press) · `type` (a single key; one per typed character, gain 0.3) · `ding` (a notification) · `chime` (success or a check) · `tick` (a tiny UI tick) · `thud` (a soft heavy landing) · `glass` (a glass clink) · `boing` (a cartoony bounce) · `shimmer` (a sparkle).

Keep it musical and sparse: roughly 1–3 cues per second at the most, except for typing.
