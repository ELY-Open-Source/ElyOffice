# 0.1.18

- Released 5 days after 0.1.17: the user asked to release as soon as ElyMail's cut-off letters and off-centre badges and issues #118 to #121 were fixed.
- 1 fix was made after its last review failed and has not been reviewed again (R15.11g); its review needs a Windows machine with Microsoft Office.
- 43 task lines are marked `[!]` in `tasks/TASKS.md`, each with what is left; two of them, R21.19a and R21.19b, were since fixed by R22.1 (aa4c4634), so 41 still wait on review rounds used up or on something outside the project.
- Kernel patches 0147 to 0170; gpui patch 0016 (Windows text leaves the font's line gap out); component library 7c29c52.
- #121: the black screen and the `saveAs failed for text.fodt` error were not reproduced on macOS or Windows; what was found and fixed is replace writing into tracked deletions (patch 0170).
- #124, the same black page and error on Windows with 0.1.17, was not reproduced with this version on Windows 7877: a 40-page DOCX with tracked changes on took 140 replaces and reads in a row, about 300 from four programs at once and 79 replaces that split paragraphs, with three saves, and no read copy failed to save and no page went black. The kernel reports this error for any save that failed without its own error, so it is most likely the export failing rather than the disk; #124 stays open until the reporter tries this version.
- #115's saves were not opened in Microsoft Office; #116's speed-up is the PR author's measurement.
- #119's document icons were checked in Finder with a copy of ElyTable carrying the key; the packaged apps are checked after install.
- Benchmarks, by the user's decision of 2026-11-26: each system keeps its last full record (macOS and Linux 0.1.16, Windows 0.1.17); 0.1.18 measures only the first open after uninstalling and reinstalling, on all three systems, and no first open after a reboot.
- No arm64 builds for Linux or Windows.
- First opens after install, measured on unreleased builds of this version: Windows 7877 with the setup built at 549e092a plus the release changes, uninstalled from 0.1.17 and reinstalled; macOS with an ad-hoc signed, unnotarized package from the same tree, ElyDoc, ElyTable and ElyShow removed and reinstalled (ElyPDF, ElyMail, ElyTree and ElyMark left at 0.1.17, as for 0.1.17); Linux with the Arch package on a fresh Omarchy (i5-13500H, llvmpipe), where no Ely had been installed and the idle engines start at the next login, so each app started its own.
- Windows' first run, 11 minutes after the install, gave ElyDoc 3973, ElyTable 1476 and ElyShow 5316 ms, with Word, Excel and PowerPoint at 10531, 3375 and 4203 ms against 4234, 1265 and 1593 for 0.1.17, while Defender made cloud requests and rescanned (13:06:40 to 13:06:50 UTC, as the run began); ElyShow's engine took 4581 ms to load the deck against 1412. That record is kept in `.work/R22/winfirsts/run1-install.md` (local). The committed record is the second run on the same install, 46 minutes after it, once Defender had logged nothing for 10 minutes: 1965, 609 and 1886 ms, Office 3656, 1500 and 1719 ms.
- macOS first opens are slower than 0.1.17's because gpui 0.3.14 changed its Metal shaders and each app's first window compiles them (669, 354 and 376 ms against 24, 18 and 20); the reasons are in the record.
