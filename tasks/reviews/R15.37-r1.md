crates/ely-office/src/save.rs:59 — `Saving::save` sends every save through the typing pause before it knows whether that save will write in place. If the tab has no file yet, or carries a risk, the save turns into the Save As panel (`save_paused` → `save_as`, save.rs:81-87), so that panel also waits. This contradicts the stated design "另存为不等" (docs/decisions.md last line, TASKS R15.37). Nothing in the kernel is exported until a path is picked, and nobody can type while the panel is open, so the wait buys nothing. During the wait the status bar shows "正在保存" (`pausing > 0` → `office.state.saving`, lib.rs:168) even though nothing is being saved and the outcome is a prompt (FILE-02).
Scenario: in ElyDoc, make a new blank document, type "abc", and press Ctrl+S 100 ms after the last key. Before this change the save panel opened at once. Now the status says "saving" for about 400 ms and only then does the panel open. If the user keeps typing, the panel comes up to 2 s after Ctrl+S. A `Risk::Sections` or `Risk::Links` tab behaves the same way.
Fix direction: send only in-place saves of a tab with a path and no risk through the pause. Run the Save As branch at once. Add a test asserting that Ctrl+S on an untitled, typed-into tab opens the panel (or calls `save_as`) without waiting and without showing "saving".
